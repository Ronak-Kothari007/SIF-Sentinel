# SIF Sentinel — AI Rules & Ethical Constraints

**Project:** SIF Sentinel
**Team:** 6Bits
**Problem Statement ID:** SIH26165

---

## 1. Purpose of This Document

This document defines the binding rules that govern all AI and ML components in SIF Sentinel.
Every team member, every model, and every piece of code must comply with these rules.
These rules exist to ensure the system is safe, honest, explainable, and trustworthy.

> **If any rule conflicts with a feature request or design decision, the rule wins.**

---

## 2. Fundamental Constraints

### Rule AI-1: AI Never Makes Safety Decisions
The AI system **identifies potential SIF precursor signals** and **prioritizes reports** for human review.
It does **not** make binding safety decisions.
All final safety decisions are made by qualified HSE officers.

```
SYSTEM: "This report shows potential SIF precursor signals. Priority: HIGH."
HSE:    "Confirm / Reject / Correct"
```

The system cannot act on a report without HSE confirmation.

---

### Rule AI-2: Never Claim Accident Prediction
SIF Sentinel does **not** predict accidents.
It does **not** forecast when or where an accident will occur.
It identifies patterns and signals in reported incidents that are associated with
historically serious injury or fatality events — and it prioritizes those reports
for immediate human attention.

**Forbidden language (never use this):**
- "This will cause an accident"
- "Accident probability: 87%"
- "This location is at risk of a fatality"
- "The model predicts..."

**Acceptable language:**
- "This report contains potential SIF precursor signals"
- "Priority band: HIGH — recommend HSE review"
- "Similar past reports: 3 reports with matching hazard profile"
- "The model flagged this as a potential SIF precursor with confidence X"

---

### Rule AI-3: Never Invent Accuracy Numbers
No accuracy, precision, recall, or F1 score may be published or presented
unless it comes from an **actual, documented experiment on real or synthetic data**.

Wrong:
> "Our model achieves 92% accuracy"

Right:
> "On our synthetic evaluation set of N=50 examples, the classifier achieved
> precision=X, recall=Y, F1=Z. Note: this dataset is small and synthetic.
> Real-world performance on OIL's historical data would require revalidation."

---

### Rule AI-4: All AI Outputs Must Be Explainable
Every `AnalysisResult` stored in the database must include:
1. The top contributing words/tokens from the LIME explainer
2. The list of deterministic safety rules that fired
3. A human-readable summary of why the priority band was assigned

HSE officers must be able to understand the system's reasoning without
reading any source code.

---

### Rule AI-5: No Confidential OIL Data
- Do not use real OIL incident data without explicit written authorization
- Prototype data must be public, synthetic, or anonymized
- Synthetic data must be clearly labeled as synthetic
- Dataset provenance must be documented in `data/README.md`

---

### Rule AI-6: No External AI APIs
All model inference runs locally on the development/demo machine.
No report text, no embeddings, no safety data is sent to:
- OpenAI
- Anthropic (Claude)
- Google Gemini
- Any other cloud AI service

This protects data confidentiality and ensures the system works without
an internet connection.

---

### Rule AI-7: Human Feedback Drives Retraining
Model updates must only use feedback that was:
1. Generated by a qualified HSE officer
2. Stored in the `feedback_log` table with a proper reviewer ID
3. Reviewed for quality before being added to the training set

Automated retraining without HSE-validated labels is forbidden.

---

### Rule AI-8: Rule Engine Is Auditable
The SIF trigger rules in `backend/rules/sif_rules.yaml` must be:
- Written in plain, readable YAML
- Each rule must have a `description` field in plain English
- Each rule must reference a safety standard or rationale (e.g., "Per OSHA 1926.502: fall protection required above 6 feet")
- Changes to rules must be version-controlled and reviewed

---

### Rule AI-9: Uncertainty Must Be Communicated
When the model's confidence is below a defined threshold (default: 0.55),
the system must display a low-confidence warning to the HSE officer:

> "Model confidence is low (confidence=0.47). Human judgment is especially important for this report."

Do not hide uncertainty from users.

---

### Rule AI-10: No Bias Amplification
The training dataset and rule engine must be reviewed for bias:
- Location bias (certain sites always flagged regardless of report content)
- Reporter bias (same person's reports always ranked differently)
- Language bias (non-native English text penalized unfairly)

Bias checks must be documented in `notebooks/03_evaluation.ipynb`.

## 3. Data Governance

### Data Sources (Approved for MVP)
The following public or synthetic data sources are acceptable:

| Source | Description | Status |
|---|---|---|
| AI4SafetyDatasets (public) | Generic safety incident text | Approved |
| OSHA Inspection Data (public) | US OSHA violation descriptions | Approved |
| Synthetic data (team-generated) | Realistic but fictional safety reports | Approved |
| OIL historical data | Real OIL incident reports | NOT APPROVED without authorization |

### Data Labeling Standards
- Binary label: `SIF-Precursor` or `Non-SIF`
- Labels assigned based on: presence of life-threatening hazard, energy source, missing barrier
- Minimum 2 team members must agree on a label
- Uncertain cases labeled `Non-SIF` and excluded from training (conservative)
- All labels logged in a CSV: `data/processed/labels.csv` with rationale column

### Data Retention
- Raw reports stored in PostgreSQL indefinitely (for feedback loop)
- No report is deleted without explicit user request
- Data exports include provenance metadata

---

## 4. Model Governance

### Model Versioning
- Every trained model checkpoint saved with version tag: `sif_classifier_v{N}.pt`
- Training configuration saved alongside checkpoint: `config_v{N}.json`
- Evaluation results saved alongside checkpoint: `eval_v{N}.json`

### Model Promotion
A new model version is promoted to production only after:
1. Evaluation on held-out test set
2. Results documented honestly (see Rule AI-3)
3. At least one team member other than the trainer reviews the eval notebook

### Fallback
If the ML classifier fails to load (model file missing, GPU OOM, etc.):
- The pipeline falls back to the deterministic Rule Engine only
- The API response includes `"model_used": "rules_only"` flag
- The UI displays: "AI classifier unavailable — result based on safety rules only"

---

## 5. Explainability Standards

### LIME Explainer
- Run LIME with `num_samples=300` minimum
- Report top-10 contributing tokens
- Store token weights in `analysis_results.explanation` as JSONB

### Rule Explainer
- Every fired rule must include:
  - Rule ID
  - Rule description (plain English)
  - The specific text fragment that triggered it
  - The severity contribution to final score

### UI Requirement
The HSE Review Detail page must show:
- Color-highlighted entity spans in the report text
- A ranked list of LIME tokens with their positive/negative contribution
- A checklist of fired rules with descriptions
- The priority score formula values (not just the final number)

---

## 6. Scope Boundaries

### In Scope (MVP)
- Text-based safety reports (English)
- Binary SIF / Non-SIF classification
- Entity extraction: Activity, Hazard, Location, Barrier, Equipment
- Priority scoring
- Explainability
- Similar report retrieval
- HSE review workflow
- Analytics dashboard

### Out of Scope (MVP — consider for future)
- Image or video analysis of safety incidents
- Real-time sensor data integration (SCADA, OPC-UA)
- Automatic escalation without human confirmation
- Multilingual support (Hindi, Assamese)
- Mobile app
- External cloud deployment
- Predictive modelling of future accidents

---

## 7. Presentation Rules for SIH Judges

When presenting SIF Sentinel to judges, the team must:

1. Describe the system as "AI-assisted, human-validated"
2. Demonstrate a complete workflow: Submit → Analyze → Review → Confirm
3. Show the explainability panel — not just the final score
4. Present actual measured metrics from `notebooks/03_evaluation.ipynb`
5. Acknowledge limitations honestly: small synthetic dataset, English-only, no real OIL data
6. Distinguish clearly between what the model does (flags potential precursors) and what it does NOT do (predict accidents)
